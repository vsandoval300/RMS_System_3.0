Premium Payments

The Premium Payment Tracker is the main entry point for managing Transactions associated with the premium payment schedule of each Operative Document. Throughout RMS-Platform, a Transaction may also be referred to as a Premium Payment or an Instalment; all three terms refer to the same record. From this view, users can monitor the status of instalments across the portfolio, filter and group records, generate reports, and drill down into the detailed ledger of an individual instalment.

Premium Payment Tracker → List

1. Overview

The Premium Payment Overview provides a high-level view of the payment portfolio before moving into the individual Transaction records. It brings together four key indicators showing the total number of Transactions and their distribution across the Pending, In Process, and Completed lifecycle statuses.

Together, these indicators provide a quick snapshot of the portfolio's size and current payment status, helping users understand how many Instalments have not yet started their settlement lifecycle, are currently in progress, or have been completed.

Overview tiles
TileDescription
Total TransactionsTotal number of Transactions registered in RMS-Platform, regardless of their lifecycle status.
PendingTransactions for which no ledger line has yet been marked as sent or received.
In ProcessTransactions with at least one ledger line marked as sent or received, but whose payment lifecycle has not yet been completed.
CompletedTransactions whose final ledger line has been marked as received, completing the payment lifecycle.
＋
These counts reflect the entire Transactions portfolio and are not affected by any filters, search terms, or grouping applied to the list below.
Premium Payment Tracker → List

2. Premium Payments List

The Premium Payments List provides the detailed view of the payment portfolio, displaying each Transaction that matches the current filters and search criteria. From this table, users can review key Instalment information, monitor payment status and progress, sort and filter records, customize the columns displayed, and access the actions available for each Premium Payment.

The visible columns can be customized using the Column Selector button in the table toolbar. Column preferences, together with the applied filters, search terms, and sort order, are preserved for the duration of the user session; the selected grouping is also remembered in the same way.

Each row represents a Transaction (Instalment) associated with an Operative Document. By default, the list is ordered by Business and then by Document, keeping all Instalments associated with the same Operative Document together.

3. Search, Filters, and Grouping

The Search and Filter Tools, located above the Premium Payments List, help users quickly narrow the Transactions displayed and locate specific Instalment records. Search terms and active filters are displayed as removable chips, making it easy to identify the criteria currently applied to the list. These tools can be combined to progressively refine the results without affecting the overall Transaction counts shown in the Overview section.

The Search box provides a free-text search across searchable Transaction information, without requiring the user to select a specific column first. As the user types, RMS-Platform looks for matching records and updates the Premium Payments List accordingly. Search can also be combined with the Reinsurer, Status, Type, and Document filters to further narrow the results.

Filters
FilterDescription
ReinsurerLimits the list to Instalments associated with Businesses belonging to the selected Reinsurer.
StatusLimits the list to Instalments in the selected lifecycle status (Pending, In process, or Completed).
TypeLimits the list to Instalments of the selected Transaction Type.
DocumentLimits the list to Instalments belonging to a specific Operative Document.

The table can also be grouped by Reinsurer using the Group by control at the top-left of the table, organizing Instalments under their corresponding Reinsurer.

＋
When the Premium Payment Tracker is opened through an Operative Document's View Instalments action, the Document filter is automatically applied, displaying only the Instalments associated with that document.

4. Payment Actions

Each Premium Payment record provides an Actions menu (⋮) at the end of its row, giving users access to the operations available for that specific Instalment. The actions displayed may vary depending on the Transaction's lifecycle status, its current configuration, and the permissions assigned to the user.

Row actions
ActionDescription
LifecycleOpens a read-only preview of the Instalment's complete settlement ledger. See 4.1 Lifecycle Preview.
ViewOpens the Instalment's detail page. See Viewing a Transaction.
EditOpens the Instalment's edit form. See Editing a Transaction.
DeleteSoft-deletes the Instalment. Multiple records can also be deleted in a single operation by selecting them with the row checkboxes and using Delete selected.
4.1

Lifecycle Preview

Selecting Lifecycle opens a quick, read-only view of every settlement leg (ledger line) generated for the instalment — the same underlying records shown in full, and editable, from the Lifecycle Premium Payment tab of the instalment's View page. It is intended as a fast way to check the state of a payment without leaving the list.

＋
The Lifecycle preview is read-only. To edit a settlement leg — set its Sent or Received date, adjust its amounts, or attach evidence — open the instalment's View page and use the Lifecycle Premium Payment tab instead.

Transaction Detail & Lifecycle

Beyond the list, each Transaction has its own creation flow, a settlement lifecycle made up of ledger lines, and a detail page where that lifecycle is reviewed and managed. This section documents that workflow end to end.

Premium Payment Tracker → New Transaction

1. Creating a Transaction

Creating a Transaction is a batch process: the user selects the Operative Document the instalment(s) belong to and the number of instalments to create, and RMS-Platform builds one sub-form per instalment.

1

Select the Document

Choosing the Operative Document loads its defaults: the next available index, its default Cost Scheme, and its exchange rate. The exchange rate is locked to 1 when the Business's currency is already US Dollars; otherwise it is taken from the Document's Rate of Exchange (ROE FS).

2

Set the number of instalments

Using the stepper, the user chooses how many instalments to create at once. RMS-Platform then renders one "Transaction Information" block per instalment, described in 1.1 Instalments Batch.

3

Complete each instalment and create

Once every instalment's fields are filled, submitting the form creates all the Transactions together, along with the settlement ledger lines each one requires.

1.1

Instalments Batch

Each instalment in the batch has its own "Transaction Information" block with the following fields.

Instalment fields
FieldRequiredDescription
IndexAutomaticSequential position of the instalment among the Document's Transactions. Cannot be edited.
Id transactionAutomaticPre-generated identifier for the instalment. Cannot be edited.
Due DateRequired*Date the instalment is due. Changing it recalculates the settlement preview below.
ProportionRequired*Percentage of the total premium this instalment represents (0–100).
Exchange RateRequired*Rate applied to convert the instalment to US Dollars. Disabled when the Business's currency is already US Dollars.
Cost SchemeRequired*Placement Scheme the instalment's premium flows through. If the Document has more than one scheme, an "All" option combines them.

Below the fields, a live Transaction Lifecycle preview shows the settlement ledger lines that will be generated for that instalment — the same calculation engine used to build the final records once the form is submitted.

＋
Once a Transaction exists, the Operative Document it belongs to can no longer be changed from the Edit form — only its Due Date, Exchange Rate, and the settlement ledger itself can be adjusted afterward.
Premium Payment Tracker → Transaction

2. Transaction Lifecycle

Every Transaction is settled through one or more ledger lines (its "logs"), each representing a leg of the premium flow between two parties. The Transaction's own status and progress are derived entirely from the status of these lines.

Definition

A ledger line's status is set automatically from its dates: filling in a Received date marks it Completed; filling in only a Sent date marks it In process; with neither date set, it remains Pending. There is no separate button to change a line's status — it always follows from its Sent/Received dates.

Transaction status rules
StatusWhen it applies
PendingThe Transaction has no ledger lines, or none of them have progressed past Pending.
In processAt least one ledger line is In process or Completed, but the last line in the chain is not yet Completed.
CompletedThe last ledger line in the chain has been marked Completed.

The Progress column shown in the list represents this same information visually: one dot per ledger line, in the order they settle, followed by the overall completion percentage.

3. Viewing a Transaction

The View page shows the instalment's core details — Index, Id, Document, Status, Exchange Rate, Due Date, Type, Proportion, and Remittance Code — along with its lifecycle progress bar, followed by up to three tabs.

Tabs
TabDescription
Lifecycle Premium PaymentThe instalment's full, editable settlement ledger. See 3.1.
Premium Payment SupportSupporting files and notes attached to the instalment. See 3.2.
Bordereaux AdjustmentsHistory of premium recalculations. Only shown when the Business's Premium Type is Estimated or Declared. See 3.3.
＋
The View page also provides an Audit info button, showing a chronological log of changes made to the Transaction record.
3.1

Lifecycle Premium Payment

This tab lists every ledger line generated for the instalment: its Deduction concept, Source and Destination parties, Due Date, Sent and Received dates, Premium, Discount, Banking Fee, Net Amount, an Evidence indicator, and its Status. Selecting Edit on a line opens its settlement details, where the Sent date, Received date, Gross Amount, and Banking Fee can be adjusted and a supporting PDF can be attached as evidence.

✓
Ledger lines are generated by the system and cannot be created or deleted manually from this tab — only their settlement details can be edited.
3.2

Premium Payment Support

This tab holds general supporting documentation for the instalment — for example, remittance confirmations or correspondence — each entry made up of a description and an attached file. Files can be previewed inline (PDFs, images, and Office documents) or downloaded.

3.3

Bordereaux Adjustments

For Businesses with an Estimated or Declared Premium Type, this tab keeps a read-only history of every Bordereaux adjustment applied to the instalment: its reference, reported premium and claims, previous and new amounts, supporting evidence, and who applied it. New records are created from the Edit page's Apply Bordereaux action, described in 4. Editing a Transaction.

Premium Payment Tracker → Edit

4. Editing a Transaction

The Edit page reuses the instalment's core fields — Due Date, Exchange Rate — together with its live lifecycle status and progress bar, and adds two additional actions for adjusting the instalment after it has been created.

Edit page actions
ActionDescription
Apply BordereauxRecords a new reported premium/claims figure from a bordereaux and updates the instalment's amount and ledger accordingly. Only available when the Business's Premium Type is Estimated or Declared.
Recalculate LifecycleRebuilds the instalment's settlement ledger from its current field values, preserving any settlement progress (Sent/Received dates, status, evidence) already recorded on lines that still apply.
4.1

Apply Bordereaux

Apply Bordereaux is used when actual bordereaux figures arrive for a Business with Estimated or Declared premium. The user enters the Bordereaux Reference, the Reported Premium, and the Reported Claims; RMS-Platform proposes the resulting Net Amount (Premium minus Claims), which can be adjusted, and evidence files and notes can be attached. Confirming the action logs the adjustment in Bordereaux Adjustments, updates the instalment's amount, and regenerates its settlement ledger to match — while keeping each line's existing Sent/Received progress and evidence wherever it still applies.

4.2

Recalculate Lifecycle

Recalculate Lifecycle rebuilds the instalment's settlement ledger from its current Proportion, Exchange Rate, Due Date, and Cost Scheme, without changing the reported premium itself. It is useful after correcting one of these fields directly, so the ledger lines stay consistent with the instalment's data. Lines that no longer apply after the recalculation are removed; the rest keep their recorded Sent/Received dates, status, evidence, and any manually adjusted Banking Fee.

＋
Changing the Exchange Rate and saving also triggers this same recalculation automatically, in addition to using the button directly.
